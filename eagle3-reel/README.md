# How EAGLE-3 Speculative Decoding Works — Instagram Reel

A ~173 s vertical (1080 × 1920, 30 fps) educational reel. Every frame is drawn with the
HTML Canvas 2D API by one deterministic function, `draw(t)`. Narration is OpenAI
`gpt-4o-mini-tts`, forced-aligned to the exact script so animation cues land on the
spoken words.

Output: `output/eagle3_explained.mp4` (H.264 High, yuv420p + AAC 48 kHz stereo, −14 LUFS).

## Files

| File | Role |
| --- | --- |
| `narration.txt` | Exact narration script, one sentence per paragraph (34 sentences). |
| `generate_audio.py` | OpenAI TTS → `audio/narration.wav` (one request, voice `onyx`). |
| `align_audio.py` | Forced alignment → `timings.json`, plus verbatim QA. |
| `timings.json` | Sentence + word timestamps, pauses, timeline (1 s lead-in, 4 s end hold). |
| `index.html` | The animation: `draw(t)`, 12 scenes, live preview player. |
| `render.mjs` | Puppeteer → `draw(i/30)` per frame → PNG pipe → FFmpeg → MP4. |
| `output/` | Final MP4, mastered audio (`audio_final.m4a`), TTS metadata, QA contact sheets. |

## Setup

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
npm install                       # puppeteer-core (uses your installed Google Chrome)
echo 'OPENAI_API_KEY=sk-...' > .env   # or export it; ../.env is also read
```

Chrome path defaults to `/Applications/Google Chrome.app/...`; override with `CHROME_PATH`.

## Pipeline

```bash
.venv/bin/python generate_audio.py --speed 1.12   # 1. narration (≈168 s)
.venv/bin/python align_audio.py                   # 2. timings.json + QA report
node render.mjs                                   # 3. inject timings, master audio, render, mux
```

`npm run stills` writes sample frames to `output/stills/` for visual review;
`node render.mjs --stills 12.5 80` renders arbitrary timestamps.

### Narration pacing

At speed 1.0 the take was 195.8 s (over the 180 s limit). Natural pauses were already short
(longest ≈1 s), so trimming silence would not have helped. The fix was a moderate TTS-side
pacing change (`speed=1.12`, generated by the model, not post-hoc time-stretching), giving
≈168 s of speech and a 173.5 s reel. No content was removed.

### Alignment & verbatim QA

The Speech API returns no timestamps, so `align_audio.py`:

1. gets word timestamps from `whisper-1` (used only as timing anchors);
2. aligns the **script's** words to them with Needleman–Wunsch (98.5 % direct matches; the rest
   are hyphenated words and "six point five", which are interpolated);
3. snaps sentence edges to real pauses detected from the RMS envelope;
4. re-transcribes with an independent recogniser (`gpt-4o-transcribe`) and diffs it against
   `narration.txt`; the result is stored in `timings.json → qa.verbatim_check`.

TTS sometimes improvises: one take said "hardware, **and** workload". That take was rejected;
the shipped take has zero differences under both recognisers.

### Audio mastering (in `render.mjs`)

1 s silent lead-in → two-pass `loudnorm` (−14 LUFS, −1.5 dBTP) → fade in/out → padded to the
full timeline (4 s end hold) → AAC 192 kbps. Optional `MUSIC=bed.mp3` adds a ducked music bed.

### Rendering

`render.mjs` opens 6 headless Chrome pages, each drawing frames `i ≡ w (mod 6)`. A bounded
reorder buffer feeds PNGs to FFmpeg's stdin strictly in order, so no frame files are written to
disk. Frame count = `round(total × 30)` from `timings.json`; the script refuses to render more
than 180 s. Because `draw(t)` depends only on `t` (seeded data, no clocks, no accumulated state),
re-rendering any frame produces the same pixels.

## Preview

```bash
node render.mjs --inject && node render.mjs --audio
open index.html                   # or: python3 -m http.server 8000
```

Play/pause (Space), ±2 s (arrow keys), −5 s button, scrubber, scene jump menu; `?t=95` deep-links.
Playback is clocked by the `<audio>` element, and every displayed frame is `draw(audio.currentTime)`.

## Editing

* **Scenes** are functions `scene0` … `scene11` in `index.html`. `SCENE_DEF` maps each scene to its
  sentence range; crossfades sit at the midpoint of the pause between scenes.
* **Timing cues** use the narration, never hard-coded seconds: `S(i)` / `E(i)` are the start/end of
  sentence *i*, `cue(i, 'word')` is when a word is spoken (e.g. `cue(7, 'draft')` highlights the
  draft model, `cue(9, 'single')` lights the parallel verification columns,
  `cue(10, 'rejected')` shakes the rejected chip, `cue(16, 'multiple')` merges the layer features).
  If the script or voice changes, regenerate audio and re-run alignment; the animation follows.
* **Colour code** (`CHIP`): beige = prompt · white/charcoal = target-generated · dashed terracotta =
  unverified draft · sage = accepted · red struck = rejected · grey dashed = discarded (depended on a
  rejected token) · blue = token supplied by the target at the first mismatch.

## Accuracy notes

* Drafting is shown as sequential steps; only target verification is parallel.
* Accept/reject uses an explicitly labelled greedy example, followed by the sampling rule
  `min(1, p(x)/q(x))` (with residual resampling), which keeps the output distribution unchanged.
* The verification pass is drawn as real target work, never free.
* The 6.5× figure is the paper's reported maximum in its evaluated settings, not a guarantee.
* Diagrams are deliberately simplified (layer count, feature taps, tree shape are illustrative).
* The asterisk motif is decorative and implies no affiliation with or endorsement by Anthropic.

Reference: Li et al., *EAGLE-3: Scaling up Inference Acceleration of Large Language Models via
Training-Time Test* (2025).
